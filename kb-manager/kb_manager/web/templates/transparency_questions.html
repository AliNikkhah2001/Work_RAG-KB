How to use for testing UTF-8 JSON

This page exposes every question stored in the KB as qa_pair chunks. Use GET /transparency/questions/json?group_by=section for RAG/guardrails benchmarks: each item has question + expected_chunk_ids=[chunk_id]. Grouped by section (= heading_path / parent_key / sheet_name) so you can run per-section hit-rate. Keyword heuristic is tunable via POST /search/api {"keyword_boost": 0..10} (env KB_KEYWORD_BOOST=3.0, see /search/config).

Hierarchy: document → sheet → parent_key → heading_path → chunk_type. Sections here are heading_path (e.g. Sheet: چت‌بات-سوال و جواب) – matches chunking parent_scope=sheet.

Benchmarks per section

To get hit-rate per section, run the retrieval check (uses current keyword_boost):

curl http://127.0.0.1:8001/transparency/questions/retrieval-check?limit=100 | jq .hit_rate
curl -X POST http://127.0.0.1:8001/search/api -H "Content-Type: application/json" -d '{"query":"چک برگشتی","keyword_boost":5}' | jq .keyword_boost_used

# Batch for guardrails/RAG: fetch all questions
curl http://127.0.0.1:8001/transparency/questions/json?group_by=section > /tmp/questions.json
# then for each question {query: q.question, expected: [q.chunk_id]} run search and compute hit@5 per section

For full benchmark plots per section, see Benchmarks – the JSON /transparency/questions/json can be fed to run_benchmark.py or turned into a temporary dataset and posted to /benchmarks/run. Future: /benchmarks/by-section will auto-group benchmark_results.json by section.
